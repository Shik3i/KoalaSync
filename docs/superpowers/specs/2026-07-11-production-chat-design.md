# Production Chat Design

## Goal

Make every chat capability documented for KoalaSync v2.6.0 complete, secure, testable, and release-ready without removing features or adding runtime dependencies.

## Architecture

Chat behavior is split into two focused modules. `server/chat.js` owns protocol validation, safe canonical payload creation, message identifiers, timestamps, room-scoped authorization helpers, and bounded in-memory history. `extension/chat.js` owns safe Markdown rendering, message/history presentation, emoji insertion, typing state and read-receipt presentation. Existing `server/index.js`, `extension/background.js`, and `extension/popup.js` remain transport and lifecycle adapters.

The server is authoritative for `id`, `senderId`, `username`, `timestamp`, and room membership. Client-provided message IDs are never trusted or reused. No chat event may address a socket outside the sender's current room.

## Protocol

- `chat_message`: `{ id, senderId, username, text, timestamp }`
- `chat_typing`: `{ senderId, username, isTyping }`
- `chat_read`: `{ senderId, targetId, messageId }`
- `chat_kick`: `{ senderId, targetId }`
- `chat_system`: `{ type, text, timestamp }`

Messages contain non-empty text of at most 500 Unicode code points. Usernames are trimmed to 30 code points. IDs are restricted to safe ASCII identifier characters and 80 characters. Timestamps are generated by the server. Chat history contains the latest 100 canonical messages and exists only while the room exists.

## UI behavior

- Enter and the send button submit non-empty messages.
- User content is escaped before the limited `**bold**` and `*italic*` formatter emits markup.
- A dependency-free emoji palette inserts common Unicode emoji at the current caret.
- Input activity sends `isTyping: true`; inactivity, blur, or message submission sends `false`.
- Remote typing state expires locally so stale indicators disappear.
- Receiving a visible remote message sends a read receipt; receipts are grouped per message and peer.
- Room history is rendered when room data arrives and cleared when leaving the room.
- System messages share one canonical schema and render without user-controlled HTML.
- Existing light/dark theme support covers the palette, indicator, messages, input, and receipts.

## Security and error handling

The UI never inserts raw user-controlled HTML. The server rejects malformed and empty payloads, uses room-derived identity, rate-limits chat events through the existing limiter, verifies read-receipt targets are in the same room, and allows kick only for the room host or a controller. Invalid events are ignored without taking down the relay. System events cannot be authored by ordinary clients.

## Testing

- Unit tests cover sanitization, canonical message creation, bounded history, safe Markdown, and emoji insertion.
- Two real Socket.IO clients cover message relay and identity, XSS escaping, history, typing start/stop, read receipts, room isolation, system-event rejection, kick authorization, and rate limiting.
- Static popup/background integration tests cover event wiring and prevent duplicate branches or field loss.
- `npm run verify` remains the release gate and includes the chat test suites.
- Chrome and Firefox builds, ESLint, locale consistency, website build, and production audits must pass.

## Scope

No private messages, file transfer, persisted chat history, advanced Markdown, or unrelated popup/server refactoring is included.
